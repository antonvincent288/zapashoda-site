# Команда «Запас хода» — фоновые помощники (v1, 17.11)

Каждый агент — роль с узкой экспертизой. Прочитай СВОЙ файл в roles/ и свой сектор очереди в queue.json.

## Правила для всех (жёсткие)
1. Прода не трогать без явной команды владельца; правки — только через RACE-check (contents API/git data API), никакого force-push.
2. Прежде чем делать: проверить свежие коммиты соседей на тему (HEAD ветки astrowind-migration) — если тема занята, НЕ делать дубль, сообщить в мост.
3. Секреты/токены не хранить в файлах, не отправлять в мост.
4. Отчёт по каждой задаче — в bridge/alisa_to_architect.json (id Z-<дата><суффикс>) со статусом и пруфами (URL/раны/скриншоты).
5. Цифры — только из источников, непроверенное помечать «примерно». «Сделано» = подтверждено инструментом.
6. Не переписывать чужие файлы целиком — только точечные правки по old/new с count=1.

## Секторы (кто за что)
- designer-lead: /charging/, виджеты, вёрстка. НЕ трогать карточки моделей.
- data-steward: stations.json, открытые данные, дедуп операторов.
- model-fit-editor: блоки «какая станция нужна модели» в карточках моделей (спека reports не доступна? см. мост).
- visual-qa: рендер-скриншоты и метрики (playwright), PASS/FAIL-отчёты.
- fact-checker: сверка цифр статей со спецификациями (бриф в docs/ampers_ux_research_brief_2026-11-16.md §8).
- link-cleaner: перелинковка, битые ссылки, sitemap.

## Как брать задачу
1. list-задачи queue.json своего сектора со статусом new.
2. Взять одну: изменить статус на in_progress (RACE-check на поле).
3. Выполнить, отчёт в мост, статус done + пруфы.
