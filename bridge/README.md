# Мост «Архитектор ↔ Алиса»

Канал связи между агентом-архитектором этого репозитория и Алисой (AI-ассистент владельца).
Файл AI_BRIDGE.json в корне — статус-файл сборки архитектора; его этот протокол не трогает.

## Файлы
- `bridge/architect_to_alisa.json` — очередь вопросов архитектора (append-only, пишет ТОЛЬКО архитектор).
- `bridge/alisa_to_architect.json` — ответы Алисы (append-only, пишет ТОЛЬКО Алиса).
- Взаимная ссылка через `answer_to`: id сообщения, на которое отвечает запись.

## Формат сообщения
```json
{
  "id": "A-0001",            // A-#### у архитектора, Z-#### у Алисы
  "ts": "2026-11-03T12:00:00+03:00",
  "from": "architect",
  "topic": "короткая тема",
  "body": "полный текст запроса",
  "priority": "normal",       // normal | high
  "expect": "answer"          // answer | review | status
}
```
- Каждая запись — НОВЫЙ элемент массива `messages`. Не редактировать и не удалять чужие записи.
- Алиса в ответах проставляет `"answer_to": "A-####"`.

## Правила (обязательные)
1. В мост нельзя помещать секреты: PAT, токены ботов, пароли, ключи терминалов Т-Кассы. Никогда.
2. Мост — для вопросов, ревью, контекста и статусов. Решения, влияющие на деньги или публикацию
   (боевой терминал, цены, публикация страниц, удаление контента), подтверждает только владелец в чате с Алисой.
3. Алиса проверяет этот мост в начале каждой сессии с владельцем и отвечает на все записи со статусом "new".
4. Архитектор не должен сам «отвечать за Алису» — очередь ответов append-only с её стороны.
5. Если запрос требует данных, которых нет в репо (коммерческие условия, тексты владельца) — Алиса вернёт
   его владельцу, а не выдумает.


## РЕГЛАМЕНТ ВИЗУАЛЬНОЙ УПАКОВКИ — ВЕЧНЫЙ (приказ владельца, 03.11.2026)
Генерация сухого, неструктурированного текста без визуальной упаковки **ЗАПРЕЩЕНА НАВСЕГДА**.
Такие черновики ломают экономику проекта. Конвейер выдаёт только продукт уровня Gamma:
визуально дорогой и сверхценный для премиум-клиента.

### Агент-Арт-Директор (Visual QA Validator) — в контуре
Проводит жёсткий визуальный аудит каждого гайда-продукта и страницы перед финальной сборкой.
Блокирует выдачу и отправляет на перегенерацию, если обнаружено:
1. Маркеры-заглушки ([ЦЕНА: …], TODO, XXX) или пустые текстовые списки (с тире/точками) длиннее 3 пунктов.
2. Отсутствие чередующихся контрастных экранов-разделителей (антрацит #1d1d1f / светлый #f5f5f7) —
   на этапе черновика контролируются структурно, на этапе сборки PDF — фактически.
3. Важные технические боли и лайфхаки не обёрнуты в закруглённые графические боксы
   с золотым акцентом **#D4AF37** (класс `gbox`).
4. Плотность уникальной хардкор-информации (схемы, инструкции, таймлайны, цифры, шаги) падает
   в пользу общедоступной «воды».

### Технический контур
- `scripts/visual_qa.py` — аудит approved-гайдов; заблокированные возвращаются на перегенерацию
  (флаг `qa_failed`), писатель (`scripts/guide_writer.py`) перегенерирует их целиком.
- Писатель вшивает QA-редактуру: до 2 попыток на главу, 3 провала = глава не публикуется.
- `VISUAL_SPEC` (в visual_qa.py) — контракт для PDF-компилятора: палитра (антрацит #1d1d1f,
  светлый #f5f5f7, золото #D4AF37, marine #003a40, acid #c8ea95), чередование фонов разделов,
  закруглённые золотые боксы для болей/лайфхаков.
