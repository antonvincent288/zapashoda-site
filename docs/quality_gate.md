## Причина
Владелец забраковал QR-буклеты ID_001-015 («ужасный») и ранее — PDF-гайды.
Оба случая: генерация reportlab (рисование строк) вместо нормальной вёрстки,
выдача владельцу без экспертной проверки.

## Правило (не менять без явного «да» владельца)
НИ ОДИН документ/файл для владельца (PDF, DOCX, буклеты, питчи, презентации)
не выдаётся и не показывается, пока не пройдёт QA-панель полностью:

1. Панель 5 дизайн-агентов, каждый проверяет СВОЮ роль как эксперт:
   - D1 Арт-директор: композиция, палитра, иерархия, соответствие стилю канала.
   - D2 Gamma-Pro (верстальщик): вёрстка — сетка, типографика, отступы, шрифты,
     движок ТОЛЬКО HTML/CSS → Gotenberg PDF. Движки «рисования строк»
     (reportlab-канва) для печатных материалов ЗАПРЕЩЕНЫ.
   - D3 Редактор: русский язык, читаемость, смысл, отсутствие канцелярита,
     сверка фактов с data/facts_pack.json (оценки — только с пометкой).
   - D4 Бренд-контролёр: антрацит/золото #D4AF37, тон бренда, правило визуалов
     04.11 (без фото портов/кабелей/логотипов), честность данных.
   - D5 Скептик: имитация взгляда владельца и клиента дилера.
     Вопрос-гейт: «Показал бы я это своему клиенту?» Ответ «нет» = брак.
2. Каждая роль даёт вердикт: ok / brak + список замечаний. Любой «brak» =
   возврат на доработку и повторный проход ВСЕЙ панели.
3. Минимум 20 контрольных точек суммарно на документ (2 полных прохода
   панели × 10 проверок, включая рендер-скриншот каждой страницы и проверку
   глазами в масштабе 100% и 50%).
4. Вердикт панели фиксируется в мосте (id QG-<док>) и в конце этого файла
   (журнал). Только после этого файл можно показывать владельцу.
5. Черновики владельцу НЕ показывать вообще — только финальные, прошедшие гейт.
