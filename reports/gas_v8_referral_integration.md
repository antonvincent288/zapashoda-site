# Контракт интеграции: Конфигуратор ОД ↔ GAS v7 → v8 (реферальные поля)

Дата: 03.11.2026. Статус: фронтенд готов и деплоен; GAS-апгрейд v8 — следующий шаг.

## 1. Что уже работает (фронтенд)

Мини-апп `/app/` перезапущен как **Конфигуратор для менеджеров ОД** (od v6):

- **Экран 1 (Выбор авто):** сетка брендов (пин-бренды Zeekr, Li Auto, Voyah, Avatr, Tesla — из `site_config.json`) + все 78 брендов/145 моделей, быстрый поиск (бренд или модель). Данные — напрямую из базы сайта (`MODELS` + `MODEL_SKU` в `catalog.py`), полное соответствие.
- **Экран 2 (Сценарий):** три крупные тач-кнопки: «Частный дом», «Квартира (паркинг)», «Только путешествия». Тексты и порядок — из `site_config.json → configurator.scenarios`.
- **Экран 3 (Чек-лист):** готовый комплект: позиции из подбора модели (badge `need` — «обязательно») + сценарные рекомендации («по сценарию»), цены и названия — из каталога с возможностью переопределения в `site_config.json → configurator.price_overrides` (id позиции → {name, price}). Менеджер может снять/поставить галочки — итог пересчитывается.
- **Оформление заказа для клиента:** форма (имя, телефон, город, комментарий) → генерация промокода → заявка в GAS → экран успеха с промокодом, расчётом кэшбэка и кнопками «Скопировать промокод» / «Отправить код клиенту в Telegram».

## 2. Определение менеджера (manager_tg_id)

Приоритет:
1. `Telegram.WebApp.initDataUnsafe.user.id` — если апп открыт внутри Telegram (меню-кнопка бота, личный заход менеджера).
2. URL-параметр `?ref=<tg_id>` — личная ссылка менеджера: `https://zapashoda-ev.ru/app/?ref=<id>`.
3. `initDataUnsafe.start_param` — поддержка ботов-команд со startapp-меткой.

Если менеджер не определён — на экране 1 жёлтая плашка «Менеджер не определён», заявка уходит с пустым `manager_tg_id` (не теряется, фиксируется без атрибуции).

## 3. Payload, который шлёт фронтенд

POST на `GAS_URL` (тот же endpoint, что у заявок), `Content-Type: text/plain;charset=utf-8`:

```json
{
  "t": "od_order",
  "promo": "ZSH-AB2CD9",
  "manager_tg_id": "108142888",
  "manager_name": "Антон",
  "tg_init": "user=%7B%22id%22%3A108142888%7D&auth_date=...&hash=...",
  "brand": "Zeekr",
  "model": "Zeekr 001 / 001 FR",
  "scenario": "house",
  "items": [{"id":1,"name":"Адаптер Type 2 → GB/T, 22 кВт, премиум","qty":1,"price":7000}],
  "total": 62190,
  "client_name": "Иван",
  "name": "Иван",
  "phone": "+7 915 123-45-67",
  "city": "Москва",
  "comment": "…",
  "website": "",
  "source": "tma_od"
}
```

Совместимость: до установки v8 текущий v7 запишет заявку в лист «Лиды» fallback-веткой (т: «od_order» в колонке Тип, модель/телефон/сумма/состав на месте; поле «Имя» пустое — поэтому в payload продублировано `name`). Заявки НЕ теряются, но атрибуция и промокоды начнут работать только с v8.

## 4. Что добавить в GAS v8

1. **Ветка `t === 'od_order'`** в `_leadDoPost`:
   - Лист «Лиды»: Тип = «Конфигуратор ОД», Колонка «Менеджер» (новая): `manager_tg_id` (+ имя через реестр), промокод, сценарий.
   - Рекомендация: отдельный лист «Промокоды» — `[код, manager_tg_id, дата, модель, сумма, статус(open/used/cancel)]`.
2. **Реестр менеджеров** — лист «Менеджеры»: `[tg_id, имя, город, салон(бренд), cashback_pct, ссылка-канал]`. `cashback_pct` по умолчанию 5, для топ-менеджеров/договорённостей 10.
3. **Верификация initData** (защита от подмены id): `secret = HMAC_SHA256(bot_token, "WebAppData")`, `hash == HMAC_SHA256(secret, data_check_string)`; передавать `auth_date` проверку свежести (≤ 24 ч). Для заявок по `?ref=` (без initData) — принимать, помечать тип «ref-link» (без подписи). Псевдокод и полный разбор — стандарт Telegram; реализовать на GAS через Utilities.computeHmacSignature.
4. **«Бонус недели»:** функция `_bonusWeekPost()` — собирает из «Промокоды»/«Лиды» топ-3 менеджера за неделю по подтверждённым заказам и кладёт готовый пост в POST_QUEUE или постит по кнопке в чате владельца (формат: «Антон из МСК, салон Zeekr, продал 3 комплекта Максимальный ход, бонус: 6 200 ₽» — без персональных данных, без ФИО/фото).
5. **Медиа в POST_QUEUE** (для рубрики «Жизза/Факап недели»): ветка `photo_url` в паблише очереди → sendPhoto с caption = text (сейчас v7 умеет только sendMessage/sendPoll — фото прикрепляются вручную).
6. **Валидация промокода у дилера:** бот-команда `/promo ZSH-XXXXXX` → статус кода, сумма, менеджер, кэшбэк; кнопка «Подтвердить продажу» (переводит статус used и фиксирует кэшбэк).
7. **Ответ фронтенду:** `out({ok:true, promo:…, manager_registered:…})` — фронтенд уже работает в обоих режимах (ответ читается, но при CORS-блокировке показывается предупреждение-фолбэк).

## 5. Роутинг и BotFather

- Роут аппа остался прежним: `https://zapashoda-ev.ru/app/` (+ `?ref=`). Зеркала в репо `zapashoda` (`index.html`, `app/index.html`) обновлены под новый апп — зарегистрированный линк `t.me/zapashoda_ev_bot/app` открывает конфигуратор нативно.
- BotFather (косметика, 1 мин): `/myapps` → «Запас хода | EV гид» → Edit Description → «Конфигуратор зарядки: 145 моделей, сценарии, промокод на скидку». Edit URL НЕ требуется (URL прежний), но если хотите отдельный путь `/app/od/` — скажите, включу за один коммит (зеркала + BotFather на вашей стороне).

## 6. Что осталось вне кода (решения владельца)

- Промокод: механика скидки 5% у дилера (как дилер применяет код — табличка в салоне или наш прайс со скидкой). Сейчас код — атрибуционный маркер.
- Кэшбэк-лимиты: 5% базово / 10% по договорённости — коэффициенты уже в `site_config.json → configurator.referral` (правится без кода).
- Список менеджеров для реестра (tg_id, имя, салон) — пришлёте, внесём в «Менеджеры» при апгрейде v8.
