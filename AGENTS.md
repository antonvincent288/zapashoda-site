# AGENTS.md — правила совместной работы агентов в zapashoda-site

Этот файл — соглашение между ИИ-агентами, которые работают в этом репозитории. Все агенты коммитят в ветку `astrowind-migration`.

## Разделение владения файлами

- **Дашборд ЭЗС (alisa-ассистент, чат)**: `site/public/dashboard.js`, `site/src/pages/dashboard/index.astro`, `site/public/charging/*.json`, `site/public/icons/*`, `site/public/manifest.webmanifest`.
- **ZH-оверлей виджетов (alisa-ассистент, чат)**: `site/public/zh_widgets_overlay.js` и строка `<script src="/zh_widgets_overlay.js?v=N">` в `site/src/layouts/ZhLayout.astro`. Принята по хэндоффу ZH 23.11 (`site/ZH_HANDOFF_20261123.md`).
- **Контент (ИИ-контентщик)**: `site/src/content/blog/**`, `site/src/content/models/**`, `llms-full*`, статические текстовые страницы.
- **Чужие файлы не переписывать.** Свой вопрос — новый файл или PR-комментарий, а не правка чужого.

## Протокол правки ZH-оверлея (23.11.2026, после инцидента «пропало меню»)

- Правки `zh_widgets_overlay.js` вносит только агент-владелец зоны (см. выше). Контентщик/гео-бот и другие потоки этот файл не трогают; если нужна правка — заявка через мост `bridge/alisa_to_architect.json` или чат владельцу.
- Перед PUT всегда перечитывать `sha` (правило 1) — на этом файле уже были RACE-конфликты: v2.39 соседки (SyntaxError от реальных переносов в строковых литералах), v2.47–v2.49 параллельного потока.
- В строковые литералы (`.textContent="…"`) вставлять код только с экранированием (`\n`, `\"`, `\\`); реальные переносы внутри литерала убивают весь оверлей (SyntaxError) — проверять esprima до PUSH (внешний файл + inner sc).
- Коммиты помечать тегом агента: `[alisa]`, `[validator]`, `[geo-audit]` — чтобы владелец видел, кто писал.
- Мобильный полноэкранный лист виджетов: включается только при `matchMedia('(max-width:820px)')`; на десктопе панель — 400px слева (v2.46). Кнопка «Виджеты» — в `.bar-side.zh-right` перед «Меню» (v2.45).

## Правила коммитов

1. Перед КАЖДЫМ деплоем перечитывать актуальный `sha` файла через Contents API — поверх него. Не кэшировать sha между сессиями.
2. Серии мелких push дают «cancelled» на автосборке — нормально: собирается последняя успешная. Класть несколько файлов одним push-батчем, не растягивать на десятки коммитов.
3. `?v=` в `site/src/pages/dashboard/index.astro` бампится ТОЛЬКО при изменении `dashboard.js` (иначе кэш браузеров держит старый JS).
3a. Для `zh_widgets_overlay.js` аналогично: любой коммит файла сопровождается одним коммитом bump `?v=` в ZhLayout.astro (+1 к текущему номеру, номер общий для всех агентов, не сбрасывать).
4. Не коммитить секреты (API-ключи, PAT) — никогда, ни в какие файлы.
5. `charging/stations.json` — живая база прода: менять только по решению владельца.
